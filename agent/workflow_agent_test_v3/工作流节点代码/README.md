2026-10-26已完成目录内全部7个Python文件复审及全量662项回归，具体范围、决定和后续平台验证见[节点代码审查与会话交接](../V3节点代码审查与会话交接_20261026.md)。

这里的两个 `.py` 文件是可独立复制进平台 Python3 脚本节点的完整代码，入口均为 `main(params)`。不依赖本机 `dc_agent` 包，也没有命令行、标准输入或人工选文件入口。平台代码由用户亲自配置。

## 1. 外部框架接入节点

复制 `外部框架接入.py`，放在 `8448 → 外部框架接入 → 4912` 的新增节点中。先修改文件开头两个常量：

- `API_BASE_URL`：本机服务地址，目前预填候选 `http://service-3.example.invalid`。以实际公司网卡 IP、监听端口和 DC 节点连通测试为准，不能填 `localhost`。
- `API_TOKEN`：与本机服务配置一致的访问令牌。当前值是占位符，未配置时脚本会明确报错。不要把实际令牌写入 `agent`、生成代码、规则或共享文档。

2026-10-20 联调补充：用户真实任务已让本机收到 POST 并返回 422，因此该次使用的 API_BASE_URL 已连通，应继续使用。422 是参数校验错误；新版接入脚本会显示具体字段，排查和重启步骤见 [HTTP 422 联调说明](../HTTP422联调排查.md)。不需要平台 PowerShell，可以直接通过真实数据任务验证。

2026-10-23 增强：接入脚本对空或全无有效名称的 GZKJG 本地返回 `agent.status=invalid_input`、`error_code=without_GZKJG`，不调用外部服务、不沿用旧代码。服务端也在入队前拦截同类输入。更新时只需重新复制本脚本并保留现场 URL/token；原14字段、4912及后半链保持。详见 [空结果诊断与修复记忆说明](../V3常见空结果诊断与修复记忆说明.md)。

输入映射：

| 节点参数 | 模板变量 | 类型 |
|---|---|---|
| `fileMd5` | `fileMd5` | String，非空 |
| `pageTitle` | `pageTitle` | String，非空 |
| `title` | `title` | String |
| `fileType` | `fileType` | String，必须为实际 xls/xlsx/csv；本次 example 为 xlsx |
| `publictime` | `publictime` | String |
| `GZKJG` | `GZK.GZKJG` | 原对象数组，或表示该数组的 JSON String |

只有平台实际提供稳定运行 ID 时，才增加可选 `workflow_run_id`，并在每次重试中传相同值。没有该字段时不需要配置，服务按完整业务输入的稳定指纹关联任务，不要生成随机 ID。

输出只映射父变量：`agent`（Array&lt;Object&gt;）→ 模板 `agent`。恰好一条记录，包含已约定的 14 个 String 子字段；额外的服务内部信息会被丢弃。

当前常量 `ATTEMPT_SECONDS=115`，为平台单次 120 秒上限预留约 5 秒收尾时间。每个 HTTP 请求连接超时不超过 5 秒，读超时不超过 22 秒，单次查询让服务器最多等待 20 秒。按 3 次尝试估算，节点最多主动等待约 345 秒；360 秒是服务首次受理后的硬上限，并不意味着平台一定能等待到第 360 秒。通常生成约 300 秒后，还需在约 45 秒内完成发布与传输；最后约 15 秒用于服务兜底。平台实际重试次数、间隔和总耗时需要用户联调核实，重试不增加服务预算。

仍在处理时，节点在本次等待窗口结束前抛出 `DC_AGENT_RETRY`，错误包含 `job_id`；平台需按现有配置重试。重试使用相同输入再次 POST，取得同一持久任务。业务终态失败则正常写回唯一 `agent` 记录并清空四个代码字段，随后由 4912 明确停止。HTTP 认证失败、协议错误、哈希不符也会抛异常，不向下游交付代码。

## 2. 动态代码执行器 4912

复制 `动态代码执行器_4912.py` 替换原 4912 的固定业务解析脚本。该脚本没有需要填写的服务地址或令牌。

输入映射：

| 节点参数 | 模板变量 | 类型 |
|---|---|---|
| `agent` | 整个 `agent` 父变量 | Array&lt;Object&gt;，恰好一条 |
| `fileMd5` | `fileMd5` | String，非空 |
| `title` | `title` | String |
| `publictime` | `publictime` | String |
| `fileType` | `fileType` | String |
| `pageTitle` | `pageTitle` | String，非空 |

输出保持：`ExcelData`（Array&lt;Object&gt;）→ 模板 `excel_data`。下游 8300 与后半链保持原映射。

执行器会检查 ready、14 个字段类型、代码文件名、版本、质量状态和 UTF-8 原文 SHA256，然后在独立字典中加载代码，调用交付源码的 `main(params)`。只传递表中五个业务字段，不传 `agent`、GZK、HTTP 认证令牌或平台的其他入参。独立命名空间用于避免交付代码覆盖包装器和平台绑定，不是安全沙箱。

解析器必须返回 `{"code": 0, "msg": "...", "ExcelData": [...]}`。`ExcelData` 必须非空，每条具备四核心字段；零值有效，数值必须有限或为有效数值字符串。名称、单位和日期不由包装器补猜，源码、数值、单位和日期均不进行业务清洗或精度转换。缺少字段、NaN、依赖导入失败、下载失败、缺少 main、语法错误或运行错误都会终止节点，不能正常返回空数组继续执行。

## 3. 配置后的验证顺序

1. 启动本机 API，从 DC 平台节点验证 `/health` 可达和令牌一致。
2. 先使用真实已有代码的任务，核对 `agent` 整体写回仍是单条对象数组，源码换行、SHA256 和版本完整。
3. 核对 4912 实际执行代码，`ExcelData` 写入 `excel_data`，后半链收到当前文件记录。
4. 用受控延迟任务核对跨节点重试时 `job_id` 保持不变；重试日志中的任务与服务记录应一致。
5. 由用户传入实际 `fileMd5/pageTitle` 完成新生成与最终业务结果验收。

仓库测试位于 `tests/test_workflow_nodes.py`，使用受控响应和本地审查过的小段源码验证节点行为，不调用真实 DC 网络或模型，不代表线上工作流已验收。
