只有02配置实际API_BASE_URL/API_TOKEN，继续使用已联通地址及原令牌。新脚本单次超时120秒、异常重试0次；原后半链超时和重试不动。

02配置fileMd5、pageTitle、title、fileType、publictime、GZKJG及agent七项输入；agent选择整个父数组，输出仍整体写回同一个agent。首次为空时提交任务，后续直接读取job_id查询。2026-10-26已恢复此配置，不使用省略agent输入的配置方式。

条件配置：

1. agent.status等于ready→4912。
2. 否则，agent.status等于processing且count小于整数常量3→回02；其余→05。
3. 4912后，agent.status等于ready且error_code为空且stage等于platform_execute_complete→原8300后半链；其余→05。
4. 原4589有效数据分支直接结束，无有效数据分支接05；05接普通结束。

agent整体映射父数组，条件选择已有子字段。最大轮数直接填条件常量3，不另建变量。第三轮ready仍正常执行；三轮约315秒主动等待。延长等待改条件常量并同步后台预算，不新增节点。

先确认DC支持回环与最新变量读写。仓库原接入/4912脚本保留历史对照，不要混用旧异常重试逻辑与本方案。
