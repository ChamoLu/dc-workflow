# 07 · 改进建议（面向 codex 等智能体）

> 以下为基于现有实现的**客观脆弱点与改进方向**，供后续改造参考。每条都标明了位置与原因，便于直接定位代码。改造时请以 [../工作流脚本原文/](../工作流脚本原文/) 中的逐字脚本为基线。

## 1. 最核心：解析器 4912 与“固定模板行号”强耦合（高优先级）

`_extract` 用**硬编码行号**（`range(4,21)`、`second_names` rows 27–41、`third_names` rows 48–60、`fourth_names` rows 66–74）和固定列（A/B/C/D）读取。风险：

- 一旦上街区月报调整表结构（增减指标行、插入说明行、调整列顺序、改变 sheet 名），解析会**静默错位**——读错行不会报错，只会产出错误指标名/数值，且部分行被丢弃。
- 改进方向：
  1. 以**指标名/表头文本**为锚点定位（按行首文字匹配），而不是绝对行号；
  2. 对每个固定区块先定位“区块标题/表头行”再相对偏移；
  3. 增加结构校验：预期 sheet 名、关键锚点单元格缺失时**显式报错**而非返回空；
  4. 利用已内置的 `_dc_validate` 证据机制，在解析失败/结构漂移时输出告警并留存证据，供回归比对。

## 2. 测试硬编码节点 2229 与生产入参混用

- 2229 直接写死 `pageTitle`/`title`，使工作流无法直接复用于真实采集；`fileMd5` 仍需运行时另传，三者来源不一致，容易在调试/生产间混淆。
- 改进方向：
  - 用平台的“调试参数/环境变量”注入测试值，而不是新增一个会写回全局字段的脚本节点；
  - 或给 2229 加开关（仅调试态生效），并在文档/节点备注中明确“生产必须删除或旁路”。

## 3. 解析器未完成 Skill 化、与生产链路重复

- 生产工作流通过 Excel 路由 Agent 从 Skill 包选择解析器并由通用执行器运行；本工作流把同一份解析逻辑写死在节点 4912。两处若各自演进会出现**逻辑漂移**。
- 改进方向：以 4912 为唯一“源”，把解析器抽取为站点 Skill 资产（携带数据源路径代码 `2085711403154546690`、`_dc_validate` 校验入口与单元格证据），生产与测试都引用同一资产；测试工作流改为“下载 Skill 版本解析器 → 执行”，避免双份维护。

## 4. 名称匹配过于严格（8300）

- 匹配采用**精确字符串相等**（`rule_name == indicator_name`），对全角/半角、空格、括号、星号、换行、别名极敏感。样例中 Excel 60+ 行最终仅匹配上约 17 条，且存在重复指标（如“规模以上工业增加值比去年同期±%”出现两次）。
- 改进方向：
  - 匹配前对名称做规范化（统一括号、去空格/星号、全半角）；
  - 增加“别名/同义词”映射与模糊匹配兜底，并对**未匹配指标**单独输出（当前是直接丢弃），便于发现规则库缺口；
  - 对重复匹配做去重或按规则库约束报警。

## 5. 单位换算的健壮性

- 7882 查不到换算率时默认 `1`（静默不换算），可能掩盖“单位未配置”的真实问题。
- 改进方向：对“单位不一致但又查不到换算率”的记录显式标记（如写入 `remark` 或计数），在条件/结果中可观测，而不是静默按 1 处理。
- 8300 在无单位时兜底 `["-"]`，会以 `-` 去查换算率（必然查不到），建议改为不发起查询并告警。

## 6. 空值拦截条件的可观测性

- 条件 4589 命中 IF 后**悬空终止**，没有任何日志/告警节点，线上难以区分“正常无数据”与“解析失败导致全空”。
- 改进方向：IF 分支接一个记录/告警/标注节点，输出失败原因（如结构校验失败、未匹配数、单位缺失数），形成可追溯的失败路径。

## 7. 数据与输出的小问题

- `indicator_data` 经 7882 后统一转为字符串（`str(Decimal*Decimal)`），可能丢失原始数值类型/格式（如 0.002719 等）；下游入库时需明确类型。
- `publictime` 在本测试中为空；标题解析只产出 `end_date`。生产化时应统一发布日期来源并校验。
- `PLPL/SJPLLB/unit_ratio/standard_unit` 等字段在本链路中基本未使用（多为空串或 null），可评估是否保留，避免字段语义不清。
- 结束节点 `data.result` 留存了一份历史调试结果（含真实业务数据），属于配置内嵌的样例快照，发布前可考虑清理，避免误导。

## 8. 安全/环境

- 脚本中写死内网 IP `http://service-1.example.invalid`，迁移环境时需参数化（文件服务基址）。
- 下载、openpyxl 解析缺少对文件大小/损坏/非 xlsx 的显式异常处理（`raise_for_status` 有，但工作簿损坏、扩展名不符时错误信息不够友好）。

## 9. 建议的改造顺序（参考）

1. 把 4912 的行号映射改为“文本锚点 + 相对偏移”，并接上 `_dc_validate` 证据做回归；
2. 抽取为 Skill 资产，消除测试/生产双份逻辑；
3. 强化 8300 名称匹配与未匹配/重复/单位缺失的可观测性；
4. 用调试参数替代 2229 硬编码；
5. 为条件 4589 的 IF 分支补失败记录；
6. 参数化文件服务地址，完善异常处理。
