## 节点 4912 · 预标注_表格解析（★核心：站点专用 Excel 解析器）

**这是本工作流最关键、也是最需要被后续维护的节点。** 它是一个**写死给“上街区·主要经济指标”Excel 模板用的 openpyxl 解析器**。在生产工作流中，这类解析器由 Excel 路由 Agent 从 Skill 包选择并交由通用执行器运行；本工作流把它直接写在节点里，便于单独调试。

### 1. 文件头注释（含站点/表元信息，务必保留）

```
# 数据源：上街区人民政府
# 数据源路径代码：2085711403154546690
# 数据来源编码：01020002879
# 路径：上街区人民政府\政务公开\政府信息公开\法定主动公开内容\统计信息\统计月报
# 目标表：usrDFJJYXSJB
# 运行时从title解析统计期；不读取GZK，生产输出不含indicator_code。
```

### 2. 依赖与常量

- 标准库：`re`、`calendar`、`io.BytesIO`；第三方：`requests`、`openpyxl`。
- 内网文件下载基址：`_DOWNLOAD_URL = "http://service-1.example.invalid/api/file/download/"`，与 `fileMd5` 拼接下载（`requests.get(..., timeout=60)`，`raise_for_status`）。
- 必须存在名为 **`主要经济指标`** 的工作表，否则抛 `ValueError("missing sheet: 主要经济指标")`。
- 用 `openpyxl.load_workbook(BytesIO(raw), data_only=True, read_only=False)` 打开（取公式计算值）。

### 3. 通用工具函数

| 函数 | 作用 |
|---|---|
| `_clean(value)` | 转字符串；去换行/首尾空白；删除 `、 , ' *` 等字符 |
| `_valid(value)` | 判定单元格是否“有值”：布尔值 False；数字 True；字符串去噪后非空且不在 `{- , —, －, --, N/A, NA}` 中 |
| `_value(value)` | 数字原样返回；字符串走 `_clean` |
| `_date_from_title(title)` | 正则 `(20\d{2})年\s*(1[0-2]|0?[1-9])月`，**且要求恰好匹配 1 次**；用 `calendar.monthrange` 取该月**月末日期**，输出 `YYYY-MM-DD`；否则返回 `""` |
| `_download(params)` | 从 `params.fileMd5` 下载 Excel 字节；缺 fileMd5 抛错 |
| `_append(records, evidence, name, data, unit, end_date, name_refs, data_ref, unit_refs, date_refs)` | 追加一条记录（`indicator_name/indicator_data/indicator_unit/end_date`），并在校验模式下记录该条每个字段来自哪些单元格（证据） |
| `_annotation(value)` | 专门解析“提高/上升/增加 N 个百分点/百分点”，返回 `(数值, 单位)`；用于第 20 行的特殊口径 |
| `_extract(ws, title, evidence)` | 按 4 个固定行块解析（见下） |
| `_run(params, with_evidence)` | 下载→打开→取表→`_extract`；返回 `{"code":0,"msg":"success","ExcelData":[...]}`；校验模式额外带 `_dc_evidence` |
| `main(params)` | `_run(params, False)`，正常输出 |
| `_dc_validate(params)` | `_run(params, True)`，**测试钩子**：返回每条记录到单元格的溯源证据 |

### 4. `_extract` 的四块“硬编码行映射”（脆弱点，也是改造重点）

脚本按**固定工作表名 + 固定行号 + 固定列**读取，共四块。列约定：通常 A=指标名、B/C=累计值、D=同比值（第三块只用 B 列）。

**第一块（rows 4–20）：主要经济指标，累计列 C、同比列 D**
- 跳过空标签；`row==10` 显式跳过。
- 单位规则：默认 `万元`；第 12 行=`吨标准煤`，第 13 行=`吨标准煤/万元`，第 20 行=`%`。
- 增长指标命名：第 18、19 行后缀为“**比年初增长**”，其余为“**比去年同期±%**”。
- 累计列 C 有值 → 产出“指标名**累计**”（单位按上述规则）。
- 同比列 D：第 20 行走 `_annotation`（把“提高 N 个百分点”解析成数值+单位“百分点”）；其余有值则产出“指标名 + 增长后缀”，单位 `%`。
- 证据中引用了脚注：`A21` 规定“带星指标增长口径为比年初增长”。

**第二块（rows 27–41）：规模以上工业增加值及子项**
- 用字典 `second_names` 把行号映射成完整指标名（制造业、电热气水、非公有制、大中型、高技术、高新技术、战略新兴、主导产业合计及装备制造/铝冶炼/非金属矿物制品等）。
- 累计列 C（其中占比重的 33/35/37 行单位为 `%`）+ 同比列 D（单位 `%`）。

**第三块（rows 48–60）：固定资产投资完成额，仅有同比列 B**
- 字典 `third_names` 映射行号（总投资、工业/房地产/基础设施/民间投资、按产业类型分、按建设性质分等）。
- 只读 B 列，统一产出“指标名 + 比去年同期±%”，单位 `%`。

**第四块（rows 66–74）：社会消费品零售总额**
- 字典 `fourth_names` 映射行号（总量、限额以上/以下、批发/零售/住宿/餐饮业）。
- 累计列 C（单位 `万元`）+ 同比列 D（单位 `%`）。

### 5. 输出

- 正常：`{"code":0,"msg":"success","ExcelData":[ {indicator_name, indicator_data, indicator_unit, end_date}, ... ]}`。
- 校验：在上述基础上为每条记录附带 `_dc_evidence`，每项形如：

```json
{
  "record_index": 0,
  "name_refs": ["主要经济指标!A4", "主要经济指标!C3"],
  "data_ref": "主要经济指标!C4",
  "unit_refs": ["主要经济指标!C2"],
  "date_refs": ["runtime:title"]
}
```

即记录每个字段取自哪个单元格（指标名/单位/数据/日期），便于人工核对和回归校验。

### 6. 与生产链路的差异（重要）

- 生产工作流的同名节点是“**通用代码执行器**”：只校验入参 `PythonFile/PythonCode` 然后 `exec` 运行 Agent 下发的解析器；本工作流直接把**特定站点的解析器写死**，节点输入只有 `fileMd5`、`title`，**不再有 `PythonCode/PythonFile`**。
- 调试通过后，通常应把本脚本内容抽取为 Skill 资产（对应数据源路径代码 `2085711403154546690`），由生产工作流的 Excel 路由 Agent 动态调用。

## 节点 8300 · 预标注_表格数据匹配（名称匹配 + 单位收集）

**输入**：`ExcelData`（解析结果）、`GZKJG`（规则库对象数组）、`publictime`（外部发布日期）、`PLPL`（频率，实际对象内未直接使用）。

**逻辑**：
1. 双重循环：对每条解析记录，按 `indicator_name` 与 `rule_indicator_name` **精确字符串相等**匹配；命中即：
   - 挂上 `indicator_code=rule_indicator_code`、`KB_unit=rule_constant_name`、`unit_ratio=rule_unit_ratio`，并透传 `indicator_data/indicator_unit/end_date/publictime/remark`；
   - 记录字段还包含 `PLPL`、`SJPLLB`（本工作流中 `SJPLLB` 固定为空串）。
   - 每条解析记录只匹配第一条命中的规则（`break`）。
2. 同时对**采集单位**与**库表单位**分别去重收集，形成 `indicator_unit_array`、`KB_unit_array`；为空时兜底 `["-"]`，组成 `unitArray`（供 4551 查换算率）。
3. 若 `matched_count == 0`（一个都没匹配上），输出单条 `indicator_code="empty"` 的占位记录。

**输出**：`OUTDATA`（即 `out_data`）、`unitArray`。

> 说明：未匹配上的解析记录会被直接丢弃（不进入 OUTDATA），这也是“Excel 里有 60+ 行、最终 out_data 只有十几条”的原因。

## 节点 7882 · 指标单位清洗（Decimal 单位换算）

**输入**：`OUTDATA`、`unitArray`（含 4551 回填的 `convert_ratio`）。

**逻辑**：
1. 兼容 `unitArray` 的列式结构（`indicator_unit / KB_unit / convert_ratio` 三列，按最短长度对齐），构建 `(采集单位, 库表单位) → convert_ratio` 的映射。
2. 逐条记录按 `(indicator_unit, KB_unit)` 查换算率；查不到时默认 `"1"`。
3. 用 `Decimal` 计算 `indicator_data = Decimal(数据) * Decimal(换算率)`；`to_decimal` 对空值/非法值/列表/带逗号字符串做了容错。
4. 当 `indicator_data` 为空或 `"empty"` 时跳过换算（保留原值）。

**输出**：换算后的 `OUTDATA`。

## 节点 5230 · 内审_数据为空清洗（剔除无效行）

**输入/输出**：`OUTDATA` → `OUTDATA`。

**逻辑**：逐条剔除以下记录：
- `indicator_code` 为空或 `"empty"`（忽略大小写）；
- `indicator_data` 为空或 `"empty"`；
- `end_date` 为空。

若全部被剔除，保留一条占位：

```json
{ "indicator_code": "empty", "indicator_data": "empty", "end_date": "", "remark": "empty" }
```

该占位用于让条件 4589 明确判定“无有效数据”并拦截。
