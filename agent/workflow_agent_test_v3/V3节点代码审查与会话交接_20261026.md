## 5. 已知限制与保留问题

- DC是否允许本连线回环、是否读取最新全局变量、叶子条件显示为String还是String数组、多个互斥分支汇入05是否任一路可触发，必须实际配置验证。若平台要求专用循环组件，按组件组织02/03及判断，业务接口无需增加字段。
- Python普通异常捕获不能覆盖平台硬超时、进程强杀、结束节点不可用或原8300/4551/7882/5230自身抛错。配置错误导致03收到错误类型count时会明确抛错；它是纯计数节点，不接收agent承担诊断格式化。
- 独立命名空间防止普通绑定冲突，并非不可信Python代码的安全沙箱。外部生成代码仍可能因平台依赖、下载环境或运行时数据差异执行失败，04会尽可能提供阶段诊断。
- 原5230中`str(item.get("indicator_data") or "")`可能把数字0当空值；04保留零值，但不能恢复后半链已删除记录。本轮未修改5230；若真实出现此类问题，应检查后处理，不让生成代码修改真实数值规避。
- OUT_DATA_EMPTY是后处理无有效输出的诊断，不证明一定是日期错误。应先核查excel_data、GZK名称/编码及下游清洗，再定位end_date；没有可靠日期来源不能补猜。源表正确但GZK未覆盖时不能反向造名。
- MODEL_STREAM_ERROR属于外部模型调用链的失败信息，应保留实际stage和安全message；不能仅因4912接收非ready而把根因归为Python执行器故障。新版通过分流和错误输出避免只得到DC_AGENT_NOT_READY。
