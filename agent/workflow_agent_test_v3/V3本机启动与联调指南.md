# V3 本机启动与联调指南

日期：2026-10-20。V3 代码版本为 0.3.0 及后续诊断补丁，服务、持久任务、独立 worker 和两个平台脚本已经实现；**用户已确认真实 DC 全流程测试通过**。当前面向 Windows 本机 Conda `dc` 环境，平台节点由用户亲自配置；服务器迁移留作未来必须完成的工作。完整原理见 [技术说明](V3整体流程与技术实现说明.md)，工程验证与用户验收分别记录在 [V3 实施与验证记录](V3实施与验证记录.md)。

## 1. 初始化和启动

在 PowerShell 中执行：

```powershell
conda activate dc
cd D:\EDBPythonCode\dc_workflow\agent
python run_service.py init-config
python run_service.py check-config
python run_service.py serve
```

`init-config` 在 `runtime/service/service.env` 新建独立服务配置和随机访问令牌。再次执行会保留现有文件，不轮换令牌。原 `.env` 中模型、地址、密钥和修复参数继续沿用；服务配置在读取原 `.env` 后叠加。`check-config` 只核对配置，不发送模型请求。

打开 `runtime/service/service.env`，将 `DC_API_TOKEN=` 后面的值复制进工作流接入脚本的 `API_TOKEN`。这不是模型密钥；不要把令牌放进 `agent` 变量或生成解析器。本次交付的节点源码保持占位符，便于安全传阅。配置示例见工程根的 `service.env.example`，无需再安装用户已经准备好的 FastAPI/Uvicorn。

初始化配置默认监听 `0.0.0.0:8765`，使公司网络有机会访问本机；工作流调用地址应使用实际公司网卡 IP。当前脚本预填 `http://service-3.example.invalid`，它是已读取到的候选地址，需要通过平台脚本执行环境验证。`0.0.0.0` 是监听地址，`localhost/127.0.0.1` 在平台脚本里指向平台自身，均不是应填写的本机调用地址。

需要只做本机健康检查时，可以临时运行：

```powershell
python run_service.py serve --host 127.0.0.1 --port 8765
```

启动后，在另一个 dc PowerShell 窗口检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
```

应返回 `status=ok`、`protocol_version=3`。健康检查不下载文件或调用模型。实际测试期间保持启动窗口、电脑和公司内网连接在线；在服务窗口按 Ctrl+C 停止服务，当前生成任务会明确标记中断。

本轮没有更改 Windows 防火墙或公司的网络路由。如果本机健康接口成功但平台无法访问，应先解决“DC 脚本运行环境 → 本机 IP:8765”的连通性，再排查生成逻辑。本机浏览器可访问不能证明平台脚本运行端可访问。

2026-10-20 真实联调更新：用户通过真实任务已经让本机收到 POST 并返回 HTTP 422，说明该次地址已连通，无需平台 PowerShell 或额外健康节点。当前应检查提交参数；已补字段级诊断，按 [HTTP 422 联调排查](HTTP422联调排查.md) 重启本机服务、更新接入脚本后仍用同一任务复测。

## 3. 任务、重试与时间预算

服务先将任务保存到 `runtime/integration_jobs.sqlite`，再由一个独立生成 worker 调用原 AssetService。请求断开后任务继续运行。HTTP 服务进程和 worker 各自创建数据库/模型连接，不在请求线程中同步等待整个生成流程。

优先使用平台真实提供的稳定 `workflow_run_id`：同 ID、相同规范化输入始终查询原任务；同 ID、不同输入返回 HTTP 409。没有稳定运行 ID 时不用额外添加变量，服务按规范化业务输入的 SHA256，在默认 900 秒有效期内复用任务。相同输入的重复手工测试在该窗口内也被视为同一个任务；这属于当前回退策略的限制。更换 fileMd5、GZK 等输入会形成另一任务。不要每次重试生成随机 UUID。

| 范围 | 默认预算与行为 |
|---|---|
| 每次平台接入脚本 | 主动工作至约 115 秒，给平台单次 120 秒限制留约 5 秒收尾 |
| 每次 HTTP 查询 | 服务最多长轮询 20 秒；连接和读取各自受剩余时间约束 |
| 三次尝试的主动等待 | 约 345 秒；实际次数、重试间隔和总时长需由平台实测确认 |
| 后台生成 | 从首次受理起算约 300 秒，排队也占该预算；不给重试重新计时 |
| 后台任务硬上限 | 首次受理起 360 秒，监督器终止逾期 worker 并标记失败 |
| 原本地 CLI | 保留原任务预算与原有调用方式，默认 600 秒 |

300 秒生成预算内，下载、预检、模型调用和本地执行都使用实际剩余时间。已有验证通过的候选可以在生成预算结束后进入择优回退和发布；通常应在最后一次平台等待结束前完成。345 秒主动等待与 360 秒硬上限并不等同，不能保证到第 360 秒才完成的任务仍被当前平台运行接收。

仍在处理时，接入脚本抛出包含 `job_id` 的 `DC_AGENT_RETRY`；重试会重新 POST 相同输入并找到原任务，不依靠失败节点写回变量。平台是否对脚本异常按配置重试，需先受控验证。终态失败则写回唯一 `agent`，清空代码字段，4912 明确停止。

服务重启、worker 异常退出会把正在处理且持有 worker 标记的任务记为中断，不声称能够从任意生成步骤自动续跑。已 ready 的结果和不可变版本仍可查询。需要新一轮独立尝试时传新的真实运行 ID，或无运行 ID 时等待默认指纹复用窗口结束；不要直接编辑 SQLite。

首版一个生成 worker 串行处理任务，适合当前单文件人工测试。队列等待占预算，不保证多个并发新来源都能在本次窗口内完成。

## 4. 接口与诊断

除健康接口外，均需 `Authorization: Bearer <DC_API_TOKEN>`：

| 接口 | 返回和用途 |
|---|---|
| `GET /health` | 最小健康状态和协议版本 |
| `POST /v3/excel/jobs` | HTTP 202，`job_id/status`；请求为六个业务字段及可选 `workflow_run_id` |
| `GET /v3/excel/jobs/{job_id}?wait_seconds=20` | HTTP 200，`{"agent": [{...14字段...}]}` |
| `GET /v3/excel/jobs/{job_id}/reports/{report_name}` | 允许的质量/验证/选择报告 |

公开 API 只接受 Excel/CSV 文件类型 `xls/xlsx/csv`，不接受本机路径、参考文件路径、强制重建、恢复参数或模型凭据。GZK 空名称尾行沿用 Task 过滤审计规则，至少需要一条有效名称；不改变 GZK 的业务含义。

ready 只从任务绑定的 `.versions` 不可变正文读取，核对来源、类型、契约、版本和原始 UTF-8 字节 SHA256，再返回完整 `PythonCode`。不通过可变的当前文件指针读取，避免生成与查询之间被新版本覆盖。对外 `report_ref` 是相对 API 路径，拼到同一个 `API_BASE_URL` 后带令牌查询；不会把服务器磁盘路径作为可调用地址。

`quality_status=accepted` 表示沿用现有校验通过的资产；`usable_with_warnings` 表示仍有质量意见，完整意见见报告。ready 表示有代码可交付，不代表本次平台的解析结果已经验收，更不能代替源表语义和完整性审查。

原框架诊断仍在 `runtime/tasks/<内部task_id>/`；API 对外 `job_id` 与其不同，集成任务记录保存两者对应结果。报告只开放白名单文件名，不接受任意磁盘路径。访问令牌和模型密钥不进入 agent；异常不向平台回显原始凭据或模型响应。

## 5. 用户实际验收顺序

1. 启动本机服务，确认本机 `/health` 为 ok，再确认 DC 脚本运行端能够访问本机内网地址。
2. 配置两段脚本和父变量映射，先选择有已登记代码的真实来源，确认 `agent.status=ready`、代码完整、`cache_hit="true"`，4912 下载本次文件执行。
3. 选在 `rule/todo.xlsx` 唯一登记且尚无代码资产的来源，用真实 `fileMd5/pageTitle` 测新生成。原始源和规则应具备足够信息；API 不会为了测试擅自删除已有代码或强制重建。
4. 核对跨尝试的 `job_id` 一致，生成完成后接收同一固定版本，再确认 4912、8300 和后半链输出本次正确结果。
5. 更换同来源的实际文件或期间再测，核对复用的是解析代码，数据仍由本次 fileMd5/title 决定；核对错误任务没有沿用旧代码或旧数据。

用户已亲自测试并确认整体流程通过，本阶段 Demo 目标已达成。以上步骤继续作为复现和后续回归方法；工程离线回归、本机 HTTP 冒烟、历史资产回放与用户平台反馈分别提供证据，不将其数量混为一谈。
