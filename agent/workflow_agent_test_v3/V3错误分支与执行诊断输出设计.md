# V3错误输出：复用agent现有字段

2026-10-25修订：当前只新增整型count，agent使用现有13个String字段，01只初始化count，不增加其他全局变量或子字段。配置与代码以 [循环接入工作流节点配置手册](V3循环接入工作流节点配置手册.md) 为准。

条件节点直接判断agent.status和count：ready进入4912；processing且count小于常量上限继续查询同一个任务；其余进入错误信息整理。4912执行后，继续通过agent.status、agent.stage及agent.error_code确认结果，失败不进入业务后半链。

错误信息复用以下已有字段：

| 字段 | 用法 |
|---|---|
| agent.status | 本次工作流当前观察或处理状态，沿用ready/processing/failed/review_required/invalid_input |
| agent.stage | 外部阶段原样保留；平台错误使用platform_*，等待结束使用workflow_wait |
| agent.error_code | 外部原始错误码，或明确的本地执行/等待错误码 |
| agent.message | 有界、脱敏的原因、计数、异常类型及代码行号等说明 |
| agent.job_id | 关联同一个后台任务 |

平台修改agent表示当前工作流处理结果，不会修改后台job状态。例如后台任务仍在处理中，平台等待次数已用完时，agent可记录failed/workflow_wait/WORKFLOW_WAIT_TIMEOUT，并在message明确写明最后观察到processing，不能将其描述成模型失败。

4912只执行ready代码，成功保持ready并写stage=platform_execute_complete；失败使用platform_*阶段并清空源码交付字段。错误整理正常返回agent及空out_data，接普通结束出口，以便用户读取诊断。

保留原8300、4551、7882、5230及4589。原4589的无有效数据分支连接错误整理，正常分支继续原结束节点；不增加成功结果包装节点。源单位转换仍交给4551/7882，不为命中GZK改造源数据。

错误阶段、原因及平台执行位置直接写在agent.message，通过job_id关联后台日志，不假称已保存进后台报告，也不增加平台结果回传接口。平台硬超时、强制终止或旧节点自身抛错仍需要平台正式异常路径支持。
