# V2候选保留、有限改进与完整质量报告

日期：2026-10-20；适用版本：0.2.2。本文替代旧版本“最后候选失败则整个生成失败”和“完整性意见不触发任何改进”的行为。

## 1. 业务结果

candidate-0或后续任一Python候选通过基本校验后，立即加入保留集合。后续修复失败、模型中断或总时限耗尽时，从集合中选择可用版本发布。只有全部候选都没有通过基本校验时，才返回无资产的失败结果。

基本校验包括实际下载bytes的本地执行、非空ExcelData、四字段类型、严格JSON、数值与源单元格一致、逐条真实来源证据以及已有日期检查。编译失败、运行失败、空结果、源数值不一致或证据虚构的候选不进入集合。允许部分提取不会使这些机械失败变为通过。

模型语义审查继续如实输出approved和完整原因。程序优先选择语义已接受的候选；同一审查等级下比较真实数据格位的去重覆盖数，再比较是否仍有完整性改进项；完全同等时保留更早的候选。保留实际重复源记录，但不以重复输出条数或GZK命中数提高排名。

如果没有语义已接受版本，业务允许保留基本校验通过的Python代码。此时必须标记quality_status=usable_with_warnings，semantic_status=issues_found或unverified；原始失败审查不改写，发布验证报告另加usable_candidate_fallback警告。它表示代码可复用且仍有待核验事项，不表示名称、层级或全部语义已经正确。模型提出的错误归属等问题与遗漏分开保留，不能仅改标签掩盖。

Markdown提示词没有在框架内实际执行提取，不能声称“已提取有效数据”；它仍需结构和语义审查接受后才进入保留集合。生产Python的main(params)、code/msg/ExcelData及四字段接口不变。

## 2. 改进预算和停止条件

| 配置 | 默认值 | 含义 |
|---|---:|---|
| DC_MAX_REPAIRS | 4 | 首次生成之后，最多再进行4次模型修复 |
| DC_MAX_QUALITY_REPAIRS | 2 | 单纯完整性改进最多2次，包含在总修复预算内 |
| DC_REPAIR_PATIENCE | 2 | 已有可用候选后，连续2轮择优评分无改善就停止 |
| DC_TASK_TIMEOUT | 原配置600秒 | 模型/任务总预算；耗尽时选择此前已验证候选，不再启动模型修复 |

没有可修复问题时直接结束。模型指出明确遗漏或前轮格位消失时，可进行有限改进；不因为仅少列了设计/审查section就反复检查。正确性问题与机械错误共享总修复预算。预算不是必须耗尽的调用次数；连续无进展可以更早结束。

修复模型收到上一轮问题、机械反馈及保留候选信息。若最近版本已损坏，会同时提供较早的可用基线，要求小范围修正并保留已验证逻辑。原有模型单次超时、重试和资产发布租约仍有效；基础设施/发布失败不会被伪装为成功。

现有.env中的三项修复配置已同步为4/2/2；模型地址、模型名称、密钥及其他配置保持原值。.env.example同时更新，后续部署可按业务调整。

## 3. 返回结果与完整报告

ready表示已有可复用资产，是否仍有问题要同时看artifact.quality_status和artifact.selection。新增的字段包括：

```json
{
  "quality_status": "usable_with_warnings",
  "selection": {
    "selected_attempt": 0,
    "latest_attempt": 2,
    "fallback_used": true,
    "semantic_status": "issues_found",
    "stop_reason": "no_progress",
    "record_count": 67
  }
}
```

selection还记录源格位数和选中代码SHA256。上述JSON是字段节选，67条来自本次旧候选回放，不表示所有任务都应输出67条。

默认报告位置均在D:\EDBPythonCode\dc_workflow\agent\runtime：

| 文件 | 用途 |
|---|---|
| tasks/任务ID/quality_report.md | 人可直接阅读的完整报告，列出所有候选、完整原因和对应原报告路径 |
| tasks/任务ID/quality_report.json | 同一报告的结构化数据，包含选择结果、选中候选问题、各轮检查/模型原意见及中断信息 |
| diagnostics/quality_issues.jsonl | 跨任务追加总账，一行一个带问题的实际运行事件，含任务来源、各轮问题、选择结果及完整报告路径 |
| tasks/任务ID/validation-N.json | 第N候选的原始运行和验证结果；语义拒绝不会因回退而被抹去 |
| tasks/任务ID/review-N.json | 第N候选的完整模型语义判断，只有真正进入审查才存在 |
| tasks/任务ID/retained_candidates.json | 可用候选快照、报告和上下文指纹 |
| tasks/任务ID/selection.json | 最终选用哪个候选、为何停止及质量标记 |
| tasks/任务ID/repair_interruption.json | 模型修复/审查中断的完整原因，仅中断时存在 |

结果diagnostics返回quality_report、quality_report_markdown、issue_log的绝对路径；真正失败时error也包含报告路径。短error.message仍可用于终端浏览，完整原因以报告为准。总账采用JSONL以支持持续追加，程序加跨进程锁避免并发串行内容交错；正常缓存命中不重复记账，直接返回原资产报告路径。纯成功且没有问题时不向问题总账追加事件。

总账同时保留后来已解决的早期失败，是否仍未解决要看selected_candidate_issues、selection和各轮review，不能把历史失败都当作当前版本失败。任务报告只汇总检查及原审查，不复制全部输出记录；完整记录和证据保留在各轮validation文件中。

## 4. 恢复及重建

正常重新生成：

```powershell
cd D:\EDBPythonCode\dc_workflow\agent
python run_agent.py run --example example --source-path runtime/source_cache/example.xlsx --rebuild
```

恢复已保存的失败任务：

```powershell
python run_agent.py run --task-id 2137e246-f1be-466a-83d0-fc054e2c1c9c --retry --rebuild --resume-candidate
```

已有缓存资产时需要--rebuild才能进入恢复/生成。恢复会重新检查真实源hash和当前参考上下文，并实际执行较早候选；只有完整上下文指纹一致时才继承已保留的语义判断。上下文变更后只能保留当前重新通过基本校验的代码，不能宣称旧语义批准仍有效。源bytes变更仍拒绝跨源恢复。
