# source_rules_v2：任务表、可选名称参考与宽松完整性规范

本规范是现有生成 Skill 的任务级适配，优先于其离线批处理、旧参考文件前提和强制完整性要求。
程序已经按原始pageTitle从todo.xlsx定位唯一任务，task_info.fields包含当前任务行的来源、路径代码、名称逻辑、标准化规则和目标表等信息；只使用实际提供的字段，不编造未知元数据。
程序按fileType从IndicatorName_Excel_Md.xlsx（Excel及PDF/图片等Markdown链路）或rule_html.xlsx（HTML链路）精确选取DataSourcePathCode同名Sheet，存在时放在references中。只使用实际提供的内容；参考列表为空时直接结合任务信息和真实文件生成，不要求补文件，不添加“无名称/正则参考”等缺失说明。
名称工作簿相当于原GZK_IndicatorName名称拼接参考：A–J非空片段帮助理解拆解，K列辅助核对参考名称。HTML工作簿相当于原GZK_IndicatorName_html名称/正则参考。参考Sheet可能没有表头，第一行也可能是规则，不能默认跳过。参考正则必须按实际接收到的转换Markdown核验，不能改为读取原始HTML。
参考资料可能过期或错误。先核验本次真实文件；冲突时在design.reference_conflicts或review.reference_conflicts写明具体参考位置、源位置和采用源事实的依据，按真实文件生成。已按源事实解决的参考冲突不阻断任务。审查头只记录实际使用的参考及其定位，不声称读取了其他离线excelrule/md_rule等文件。

必须先检查全部原始 Sheet/Markdown 内容和表头，再形成提取设计，然后生成。
源事实优先；GZK 仅辅助核对名称，不可反向造名、补值或推断单位、日期。
尽量保留有效源指标，即使名称参考或GZK未覆盖；不默认去重。参考名称和正则不是源指标全集，不得作为生产Python输出白名单。
名称拼接只保留真实业务语义；同级不能继承；独立单位、统计期间、位次和脚注不拼入名称。
上述统计期间指具体年月、季度等实际时间标签；当期、累计、同比等用于区分指标口径时是业务语义，必须保留，不能一概当作日期删除。
允许 NFKC、去换行、首尾无意义空白、中文顿号、英文逗号和英文单引号；保留英语名称词间空格、业务符号和括号内容。
单位从源表逐记录绑定，缺失用“-”；名称内括号单位提取后仍保留括号。无单位不得根据“率”“指数”猜%。
日期首先绑定真实表题/列/行的统计期。没有可靠表内期间且运行时 title 含唯一明确统计期时，本规范允许 title 兜底，审查头必须说明；不得写死样例日期。
不使用 publictime、当前日期、下载日期补统计期；不可靠则留空并报告。
保持零、负数、原始精度，去数值千分位但不换算、不四舍五入、不计算或补附近值。
明确数值注释的窄规则：源格位整体为“提高/上升/增加 + 非负十进制数 + 个百分点/百分点”时，原数值与原单位可拆为indicator_data与indicator_unit，保留精度及原格位证据；不是百分率换算。不泛化到下降、复合比例、多数字说明或任意文本取数；无法确定时报告。

Excel/CSV：main(params) 通过 requests 或 urllib 从既有文件服务按 fileMd5 下载；返回 {code:0,msg:...,ExcelData:[四字段记录]}。
HTML：只按 markdownMD5 下载转换 Markdown，返回键同为 ExcelData，不得读取原始网页或 fileMd5。
代码仅使用标准库、requests、openpyxl、xlrd。不得 subprocess/os/shell、读凭据/工程文件、写宿主文件、安装依赖。
main 必须实际解析每次下载的文件；GZK 不进入生产 Python 的运行时输入或硬编码白名单。
输入 XLS 直接 xlrd 读取原始 bytes，数字型年份 2010.0 按年份语义处理，不改写指标数值。

提示词：运行时只有 Markdown、规则允许的 title 与 GZK.GZKJG。输出严格 out_data 包装、每记录恰好 indicator_code/indicator_name/indicator_data/indicator_unit/end_date 五字段。
必须先从真实 Markdown 形成候选，再精确唯一匹配 GZK 名称；code/name 来自同条规则，数值/单位/日期来自 Markdown；不匹配不输出。
保留原 Markdown 生成 Skill 的审查头、17 个章节与具体表格规则。禁止把 PDF/PNG 等上游类型当作运行时结构依据。

生成 Python 时同时返回全部输出记录的 evidence 侧档：record_index、name_refs、data_ref、unit_refs、date_refs。
ref 必须是 inspection 中的精确 ref（如 Sheet1!A3、L5），允许 date_refs 引用 runtime:title，单位缺失“-”可留空unit_refs。
侧档只用于验证，不改变生产四字段接口。不能用模型输出的预期数值替代真正源格位验证。
无可靠证据不得自行声明全部正确；审查发现重大歧义时 approved=false。

完整性是改进目标，不是发布门槛。已有真实有效输出时，不因少提取、未覆盖某个表块、审查未逐表块列出ref或相较旧候选少记录而拒绝；这些写入quality_findings作为质量建议即可。不要为完整性增加无休止修复。
审查approved表示已提取/提示词规定内容的基本正确性，不表示源数据全量覆盖。若仅因漏项给出approved=false，rejection_kind必须为coverage；错误数值、错误单位/日期/名称归属、伪造事实或混合问题使用correctness。运行失败、错误输出及现有接口/源证据检查仍需修正，不能以允许少提取为由放行错误数据。

2026-10-20候选保留策略：审查继续如实记录上述问题，不得为了发布把approved改为true。框架保留通过基本运行、四字段、数值与真实来源证据校验的Python候选；后续有限修复失败、中断或超时，优先选择语义审查已接受的版本，再比较真实数据格位覆盖；同等条件保留较早版本，不能用重复记录或GZK命中数抬高排名。
存在未修复的模型语义问题或审查未完成时，业务允许保留基本可用代码，但框架必须标记usable_with_warnings、原始审查结论和完整报告，不宣称全部语义正确。机械校验失败或无有效输出的代码不能成为回退版本。Markdown提示词没有实际提取执行，仍需通过结构和语义审查，不能套用“提取出有效数据”的回退许可。
修复只针对明确的源证据问题，优先在retained_candidate可用基线上做小范围修改，保持已验证正确的名称层级、数值、单位、日期及下载接口。完整性改进有独立小预算，连续无进展就停止，不追求逐格穷尽。

2026-10-23三类常见故障与修复记忆：输入GZKJG没有有效名称时前置返回精确without_GZKJG，不生成代码，也不从历史记忆补规则。源内容粗审明确无数据返回FilenoData；原始源有数据而本机执行ExcelData为空时检查选表、格式、表头、数值类型和过滤/返回逻辑，不能把代码漏提取当成源无数据。end_date为空或empty时先定位源统计期间；表内无可靠期间时，按上述规范允许本次运行时title的唯一明确期间兜底。未知日期保持空并报告，不使用publictime、当前日期或历史样例值。下游可用性只是本机估计，没有平台回传，不能宣称已经运行整个工作流。
源单位与GZK库表单位不同不构成代码问题，属于unit_conversion，不触发代码修复；换算始终交给4551/7882。源单位自身提取错误仍按源事实检查，不允许为匹配库表而改单位或数值。
repair_plan列出问题编号、源证据、输出片段、允许变动字段和历史已验证策略。只修目标问题，其他字段保持；结构化issues用于记录尚未解决问题，resolved_issue_ids只能列出本轮实际复核已修好的问题。记忆仅复用策略，不复用源事实；失败、审查未通过、出现回归的修复不能升级为成功经验，不自动修改本规范或外部Skill。
