# 04 · 节点详解 · 脚本节点（script / Python3）

共 **18 个 Python 脚本节点**。所有脚本统一为 `def main(params): ... return {...}` 形式，运行时由平台把入参塞进 `params`，把返回 dict 中对应 key 写回全局变量。脚本统一 `timeout=120`（秒），默认 `failureRetryCount=0`（仅 8448 为 1 次重试）。

> 每个脚本的**完整逐字源码**见 [工作流脚本原文/](../工作流脚本原文/)，文件名 `NN_中文名_尾号.py`。本文只做逻辑说明，不复制全文（避免与源码不一致）。
> 18 个脚本中有 3 组完全重复：**13 与 02 完全相同**（数组单位清洗）、**18 与 05 完全相同**（空值清洗）、**10** 与 05/18 功能等价但多了 `None` 防护。

## 一、规则库结果转换

### 8448 · 预标注_规则库查询转（`15_预标注_规则库查询转_8448.py`）

- **入参**：`GZK`（规则 2442 返回的列式对象，含 ZBDM/ZBMC/ZBDW/unit_ratio/indicator_release_frequency 五个数组）
- **出参**：`GZKJG` → 写入 `GZK.GZKJG`
- **重试**：failureRetryCount=**1**（唯一非 0 的脚本）
- **逻辑**：规则引擎返回的 GZK 是“按列存”的多个等长数组（所有指标的代码在一个数组、名称在另一个数组……）。本脚本按列下标把它们“转置”为按行的对象数组，每行一个标准指标：
  ```json
  {"rule_indicator_code":..., "rule_indicator_name":..., "rule_constant_name":...,
   "rule_unit_ratio":..., "indicator_release_frequency":...}
  ```
  数组长度不齐时缺失位补空字符串。这是后续所有匹配脚本统一使用的规则库形态。

## 二、路由后的“解析执行”节点

### 4912 · excel python 执行（`09_excel_python_执行_4912.py`）

- **入参**：`fileMd5`、`title`、`publictime`、`PythonFile`、`PythonCode`
- **出参**：`ExcelData` → 全局 `excel_data`
- **逻辑**：
  1. 校验 `PythonFile` 非空且非 `"empty"`、`PythonCode` 是非空字符串，否则返回 `{code:-1, msg, ExcelData:[]}`；
  2. 用 `exec(compile(python_code, python_file, "exec"), 命名空间, 命名空间)` 在隔离命名空间里执行路由到的解析器代码；
  3. 取出其中的 `main(params)`，把除 `PythonCode/PythonFile` 外的所有参数（含 `fileMd5`）透传进去并调用；
  4. 直接返回解析器的返回值（解析器内部通过 `fileMd5` 下载 Excel 并解析，返回 `{code,msg,ExcelData:[...]}`）。
- 本质：**通用“代码执行器”**，自身不写解析逻辑，只负责安全校验 + 动态加载 + 调用路由到的站点解析器。

### 5242 · html python 执行（`11_html_python_执行_5242.py`）

- **入参**：`markdownMD5`、`title`、`publictime`、`PythonFile`、`PythonCode`
- **出参**：节点声明 `ExcelData` → 全局 `excel_data`
- **逻辑**：与 4912 基本相同，但更精简（无 empty 前置校验，直接 `exec` 后取 `main`）；HTML 解析器用 `markdownMD5`（HTML 已先转成 Markdown）下载并解析。
- **⚠ 命名一致性观察（供参考，不代表运行错误）**：HTML 解析器（skill 223）的 `main` 返回字典里数据键名是 **`OUTDATA`**，而本节点声明的输出字段名是 **`ExcelData`**、下游 8300 也以 `ExcelData` 读取；Excel 解析器（skill 334）则确实返回 `ExcelData`。平台运行时如何映射这一命名差异（按字段名取或整包透传）未在配置中显式说明，迁移/改造时建议统一键名以避免歧义。

### 453 · 大模型执行（file_extract 节点，不是脚本）

Markdown 分支不走代码执行，而是大模型节点，详见 [07 文档](07_节点详解_Agent与大模型节点.md#大模型执行节点-453file_extract)。

## 三、各文件类型的解析/匹配

### 1950 · 预标注_TXT解析（`03_预标注_TXT解析_1950.py`）

- **入参**：`fileMd5`
- **出参**：`OUTDATA` → `out_data`
- **逻辑**：
  1. 从内网文件服务 `http://service-1.example.invalid/api/file/download/{fileMd5}` 下载（UTF-8）；
  2. 按行解析，每行必须恰好有 2 个逗号分隔字段（`日期,值`）；
  3. 日期若为 6 位 `YYYYMM`，用 `calendar.monthrange` 转成当月最后一天 `YYYY-MM-DD`（如 `202607 → 2026-07-31`）；非 6 位原样保留；
  4. 输出 `[{"end_date":..., "indicator_data":...}, ...]`；异常/失败返回 `code:-1` 与空数组。

### 4633 · 预标注_TXT数据匹配（`08_预标注_TXT数据匹配_4633.py`）

- **入参**：`OUTDATA`（1950 解析结果）、`GZKJG`、`publictime`
- **出参**：`OUTDATA` → `out_data`
- **逻辑**：用解析数据的 `indicator_name` 与 GZKJG 的 `rule_indicator_name` **按名称精确匹配**（break 只取第一条）；匹配上则补全 `indicator_code`、`KB_unit`、`unit_ratio`、`indicator_release_frequency`、`PLPL` 等字段，一条原始记录匹配一条规则。
- **空结果约定**：若全部都没匹配上，输出一条 `indicator_code="empty"` 的占位记录。

### 9513 · 预标注_指标代码匹配（`17_预标注_指标代码匹配_9513.py`，JSON 分支）

- **入参**：`indicator_name`、`indicator_data`、`end_date`、`publictime`、`GZKJG`、`remark`、`rid`（注：JSON 分支为单条标量上下文）
- **出参**：`OUTDATA` → `out_data`；`KB_unit` → `KB_unit`
- **逻辑**：
  1. 用正则 `^-?\d+(\.\d+)?$` 判断 `indicator_data` 是否为数字，**非数字直接置为 `"empty"`**；
  2. 用 `indicator_name` 遍历 GZKJG 按名称匹配，命中即输出完整指标记录（含代码、单位、比例、频率等）；
  3. 未匹配到任何规则时，输出一条 `indicator_code="empty"` 的记录；
  4. 同时返回 `KB_unit`（命中规则的标准单位），供标量分支后续换算。

### 8300 · 预标注_表格数据匹配（`14_预标注_表格数据匹配_8300.py`，**excel/html 共用**）

- **入参**：`ExcelData`（解析器结果，映射到全局 `excel_data`）、`GZKJG`、`PLPL`、`publictime`
- **出参**：`OUTDATA` → `out_data`；`unitArray` → `unitArray`
- **逻辑**：
  1. 用解析记录的 `indicator_name` 与 GZKJG `rule_indicator_name` **按名称精确匹配**（取第一条）；
  2. 补全 `indicator_code`、`KB_unit`、`unit_ratio`、`PLPL`、`SJPLLB` 等；
  3. **同时收集去重单位**：把匹配记录里出现过的采集单位 `indicator_unit`、库表单位 `KB_unit` 分别去重收集到数组（SQL 转换率查询用），若数组为空则填 `["-"]` 保证规则节点有输入；
  4. 无任何匹配时输出 `indicator_code="empty"` 占位。

### 2938 · 预标注_表格数据匹配（`06_预标注_表格数据匹配_2938.py`，**md 分支**）

- **入参**：`OUTDATA`（大模型抽取结果）、`GZKJG`、`publictime`
- **出参**：`OUTDATA` → `out_data`；`unitArray` → `unitArray`
- **逻辑**：与 8300 类似，但**按指标代码 `indicator_code == rule_indicator_code` 匹配**（大模型已在提示词中按 GZK 做了一次候选匹配，这里用代码复核并补全库表单位/比例/频率）；同样去重收集单位产出 `unitArray`，无匹配输出 `empty` 占位。

## 四、单位换算（“指标单位清洗”）

四个节点逻辑分两类。

### 数组型：7882（链A）＝ 13；1414（链B）（`02/13_指标单位清洗_*.py`）

- **入参**：`OUTDATA`、`unitArray`（含 `indicator_unit / KB_unit / convert_ratio` 三个列式数组）
- **出参**：`OUTDATA` → `out_data`
- **逻辑**：
  1. 先按 `(indicator_unit, KB_unit)` 组合把 `unitArray` 三列按下标对齐，建立 `(采集单位, 库表单位) → convert_ratio` 映射；
  2. 逐条 OUTDATA 用其 `(indicator_unit, KB_unit)` 查换算率，**查不到默认换算率为 1**；
  3. 对有效数值（非空、非 `empty`）用 `Decimal` 做 `indicator_data = 数值 × convert_ratio`（高精度，自动去千分位逗号）；空/empty 数据保留不动。
  4. `13`（7882 节点）与 `02`（1414 节点）**源码完全相同**。

### 标量型：184（链C）、9163（链D）（`01_指标单位清洗_184.py` / `16_指标单位清洗_9163.py`）

- **入参**：`OUTDATA`、`convert_ratio`（标量，由规则 9431/7304 查出）
- **出参**：`OUTDATA` → `out_data`
- **逻辑**：`convert_ratio` 为空/异常时默认 1（兼容 list/dict 包装，取首项或 `convert_ratio` 键）；逐条 `indicator_data = Decimal(数值) × Decimal(换算率)`。
- **差异**：9163 多了一道 `if indicator_data == "empty": continue`（JSON 分支已把非数字置 empty，直接透传不换算）；184 无此判断。

## 五、空值清洗（“内审_数据为空清洗”）

### 5230（链A，脚本10）、9684（链B，脚本18）、2657（链C，脚本05）

- **入参**：`OUTDATA`；**出参**：`OUTDATA` → `out_data`
- **逻辑**（逐条）：**删除**满足以下任一条件的记录——
  - `indicator_code` 为空或为 `empty`（忽略大小写）；
  - `indicator_data` 为空或为 `empty`；
  - `end_date` 为空。
  过滤后若一条不剩，输出占位记录：
  ```json
  {"indicator_code":"empty","indicator_data":"empty","end_date":"","remark":"empty"}
  ```
- **差异**：5230（脚本10）对 `None` 更稳健（先判 None 再转字符串，避免 `None.strip()` 报错）；9684（脚本18）与 2657（脚本05）**源码完全相同**。
- 三个脚本后分别接条件节点 **3451 / 5545 / 5545**，由条件节点根据占位/empty 决定是否终止。

> 注意：JSON 链（链D）没有独立的“空值清洗脚本”，脚本 9163 之后直接接条件节点 **2934**（同名“内审_数据为空清洗”），由条件判断 out_data 是否含 empty。

## 六、内审校验

### 2034 · 内审_区分嫌疑数据（`04_内审_区分嫌疑数据_2034.py`）

- **入参**：`OUTDATA`（节点配置里还声明了 `PLPL`，但脚本代码未使用）；**出参**：`OUTDATA`→`out_data`、`warningdata`→`warning_data`
- **逻辑**：按每条数据的 `indicator_release_frequency` 校验 `end_date` 是否为对应周期末：
  - `月`：必须是当月最后一天，否则备注「截止日期不是月末」；
  - `季`：必须是 3/6/9/12 月最后一天，否则「截止日期不是季末」；
  - `半年`：必须是 6/12 月最后一天，否则「截止日期不是半年末」；
  - `年`：必须是 12-31，否则「截止日期不是年末」。
- **处理**：支持多种日期格式（`%Y-%m-%d`、`%Y/%m/%d`、`%Y.%m.%d`、中文日期、带时分秒等）；有异常的记录**复制一份**到 `warningdata`，多个问题用「；」合并；`OUTDATA` 原样保留（不删数据）。
- 无任何异常时，`warningdata` 输出占位 `{indicator_code:"empty", indicator_name:"empty"}`。
- 脚本注释明确：**“indicator_data 为 0 不再作为异常判断”**。

### 6387 · 内审_前置校验（`12_内审_前置校验_6387.py`，533 行，是最复杂的校验脚本）

- **入参**：`OUTDATA`（节点配置里同时声明 `warningdata`，用于承接上游）；**出参**：`OUTDATA`→`out_data`、`warningdata`→`warning_data`
- **校验项**（异常追加到 `remark`，同一问题不重复，多个用「；」合并）：
  1. `indicator_code` 长度 **不等于 10 位** →「指标代码长度不是10位」；
  2. `publictime` **晚于当天系统日期** →「信息发布日期-信息发布日期大于当前系统日期」；
  3. `publictime` **早于 `end_date`** →「信息发布日期-信息发布日期小于截止日期」；
  4. 按 `indicator_release_frequency` 校验 `end_date` 周期末（月/季/半年/年，备注同 2034）；
  5. `problem_fin_time` 独立校验（该字段由规则 850/8359/1834 写入）：
     - 含 `1002` 且 end_date 非月末 →「非月末数据」；
     - 含 `1003` 且非季末 →「非季末数据」；
     - 含 `1004` 且非年末 →「非年末数据」。
- **处理**：异常记录复制进 `warningdata`；OUTDATA 原样保留；无异常输出 `empty` 占位（含 7 个空字段）。注释明确：**不再校验 indicator_data 是否为 0、不再校验 unit_ratio**。
- 日期解析支持 ISO 格式兜底。

### 4185 · 代码执行（`07_代码执行_4185.py`，合并节点）

- **入参**：`OUTDATA`、`warningdata`；**出参**：`OUTDATA` → `out_data`
- **逻辑**：仅一行核心逻辑——`OUTDATA.extend(warningdata)`，把人工标注修订后的问题数据（`warningdata`）追加合并进正常数据 `OUTDATA`，作为最终输出送往结束节点。

```python
def main(params):
    OUTDATA = params.get("OUTDATA", [])
    warningdata = params.get("warningdata", [])
    OUTDATA.extend(warningdata)
    return {"OUTDATA": OUTDATA}
```
