# 05 · 节点详解 · 条件节点（condition）

共 **11 个条件节点**。条件节点按画布上的分支从上到下顺序匹配，命中第一个为真的分支即沿该分支走（IF → ELSE IF 1 → ELSE IF 2 → … → ELSE）。每个分支内部多个条件之间由 `logic` 决定是 **OR（或）** 还是 **AND（且）**。

字段操作符含义：

| 操作符 | 含义 |
|---|---|
| `contains` | 字段（数组/字符串）包含指定值 |
| `excludes` | 字段**不包含**指定值 |
| `isEmpty` | 字段为空 |

> 下文“**悬空**”指该分支在画布上**未连出任何连线**，命中即终止该条流程（不进入后续、不发送、不报错）。

---

## 一、文件类型路由（3060 / 1127，规则完全相同）

两者各 5 个分支，按 `fileType` **包含**关键字判断：

| 分支 | 逻辑 | 条件（判断字段 `fileType`） | 3060 流向 | 1127 流向 |
|---|---|---|---|---|
| IF | **OR** | contains `xls` / `xlsx` / `csv` | excel Agent 3708 | excel 标注 3209 |
| ELSE IF 1 | AND | contains `json` | 脚本 9513 | json 标注 3138 |
| ELSE IF 2 | AND | contains `txt` | 脚本 1950 | MD 标注 6472 |
| ELSE IF 3 | **OR** | contains `html` / `htm` / `shtml` | HTML Agent 763 | MD 标注 6472 |
| ELSE | — | （兜底，其余全部） | md-Agent 2204 | MD 标注 6472 |

要点：

- 用 `contains` 而非精确等于，所以像 `application/vnd.ms-excel`、`*.xlsx` 这类带前后缀的类型串也能命中。
- 分支顺序很重要：**一个文件不会同时命中两个分支**（命中首个即停）。
- `3060` 用于**解析分流**；`1127` 用于内审确认有问题数据后的**标注任务分流**。
- 标注分流里 `txt / html / 其它（含 md）` 三种都进入同一个 **MD 标注（6472）**；只有 excel 与 json 有专属标注模板。

## 二、三个路由 Agent 后的“空结果”判断（9802 / 5519 / 2950）

结构完全一致，均为 2 分支：

| 条件节点 | 所属 Agent | IF 条件（OR） | IF 走向 | ELSE 走向 |
|---|---|---|---|---|
| 9802 | excel Agent 3708 | `PythonFile` contains `empty` **或** `PythonCode` isEmpty | **悬空（终止）** | excel python 执行 4912 |
| 5519 | HTML Agent 763 | `PythonFile` contains `empty` **或** `PythonCode` isEmpty | **悬空（终止）** | html python 执行 5242 |
| 2950 | md-Agent 2204 | `PromptFile` contains `empty` **或** `PromptCode` isEmpty | **悬空（终止）** | 大模型执行 453 |

含义：路由 Agent 没有在该 `pageTitle` 对应的 Skill 包里找到解析器/提示词（文件名返回 `empty`），或返回的文件内容为空，则**终止**，不进入解析执行；只有真正选到了文件才继续。

## 三、空值拦截（2934 / 3451 / 5545）

| 条件节点 | 服务链路 | IF 条件（OR，判断 `out_data`） | IF 走向 | ELSE 走向 |
|---|---|---|---|---|
| 3451 发放_为空判断 | 链 A（excel/html） | `out_data.indicator_code` contains `empty` **或** `out_data` isEmpty **或** `out_data.remark` contains `empty` | **悬空（终止）** | 2034 |
| 5545 发放_为空判断 | 链 B（md）+ 链 C（txt） | 同上 | **悬空（终止）** | 2034 |
| 2934 内审_数据为空清洗 | 链 D（json） | `out_data` contains `empty` **或** `out_data.indicator_data` contains `empty` | **悬空（终止）** | 2034 |

含义：经过匹配/换算/空值清洗后，若数据中仍带 `empty` 占位（指标代码没匹配上、数据非数字、整体为空等），则**整条流程终止**，不进入内审、也不创建标注任务；否则进入内审脚本 2034。

> 注意链 A/B/C 在条件之前还有一个“空值清洗脚本”（5230/9684/2657，会把无效记录删掉并在全空时输出一条 empty 占位）；链 D 没有独立清洗脚本，直接由 9163 输出后由条件 2934 判断。

## 四、内审阶段

### 3064 · 内审_判断嫌疑数据（2 分支）

| 分支 | 逻辑 | 条件（判断 `warning_data`） | 走向 |
|---|---|---|---|
| IF | **AND** | `warning_data.indicator_code` excludes `empty` **且** `warning_data.indicator_name` excludes `empty` | 9075（按频率继续查日期特殊性） |
| ELSE | — | 兜底（问题数据为空，代码/名称含 empty） | 6387（前置校验） |

含义：只有当 `warning_data` 确实是一条**有效指标**（代码、名称都非 empty 占位）时，才需要按披露频率调用规则 682 做日期特殊性查询；否则直接跳到前置校验。

### 9075 · 内审_区分嫌疑数据（按频率，4 分支）

| 分支 | 逻辑 | 条件（判断 `warning_data.indicator_release_frequency`） | 走向 |
|---|---|---|---|
| IF | AND | contains `月` | 规则 850（非月末） |
| ELSE IF 1 | AND | contains `季` | 规则 8359（非季末） |
| ELSE IF 2 | AND | contains `年` | 规则 1834（非年末） |
| ELSE | — | 兜底（频率为半年/其他/空） | 6387（不查规则） |

> 注意：这里只对“月/季/年”三类频率调规则 682；“半年”频率没有单独分支，走 ELSE 直接进 6387（半年末的判断在 6387 脚本内部完成）。三条规则分支与 ELSE 最终都汇入 6387。

### 8204 · 内审_错误判断（2 分支）

| 分支 | 逻辑 | 条件（判断 `warning_data`） | 走向 |
|---|---|---|---|
| IF | **AND** | `warning_data.indicator_code` excludes `empty` **且** `warning_data.indicator_data` excludes `empty` | 1127（创建人工标注任务） |
| ELSE | — | 兜底（代码或数据仍含 empty，没有可标注的有效问题数据） | **结束 end（直接发送）** |

含义：内审完成后，只有同时具备“有效代码 + 有效数据”的问题记录才进入人工标注；否则直接结束。

## 五、悬空分支汇总（6 个，命中即终止）

| 条件节点 | 悬空的分支 | 命中含义 |
|---|---|---|
| 9802 | IF | excel 路由未选到解析器 |
| 5519 | IF | HTML 路由未选到解析器 |
| 2950 | IF | md 路由未选到提示词 |
| 3451 | IF | 链 A 清洗后仍无有效数据 |
| 5545 | IF | 链 B/C 清洗后仍无有效数据 |
| 2934 | IF | 链 D 仍含 empty/非数字数据 |

> 设计提示：这 6 个悬空分支是一种“静默拦截”——数据在该分支上不会报错、也不会产出任何结果。若希望被拦截的数据可追溯（如记录失败原因），需要在平台上为这些分支补连日志/消息节点（本次仅做只读说明，未做改动）。
